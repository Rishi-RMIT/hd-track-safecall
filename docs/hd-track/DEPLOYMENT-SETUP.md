1. Review `scripts/deployment/setup-identities.sh`. In Cloud Shell for `hd-track-safecall`, run it as project owner. It configures only free IAM/APIs, two custom roles and two service accounts. The rules identity has five Rules API permissions, no database/Auth access and no key. GitHub OIDC is restricted to numeric repository/owner IDs, `main` and push events. The separate session-server identity has only `firebaseauth.users.get` and `firebaseauth.users.createSession`.
2. Put the two non-secret output values in GitHub Settings → Secrets and variables → Actions → Variables: `GCP_WIF_PROVIDER`, `GCP_RULES_SERVICE_ACCOUNT`.
3. Only after explicit approval: generate one key for `hd-session-server`, encode it as Base64 privately, and store it as Vercel **Production only** `FIREBASE_SERVICE_ACCOUNT_KEY_BASE64`. Never put it in GitHub, Preview, source, logs or chat. The original broad local Admin key stays local.
4. Vercel Hobby: import only `Rishi-RMIT/hd-track-safecall`; framework Next.js, root `frontend`, include source outside root, install `pnpm install --frozen-lockfile`, default build/output, Node 22, production branch `main`. Production public Firebase variables come from the ignored local root .env, plus `NEXT_PUBLIC_APP_NAME=SafeCall Notebook`. No Functions, Storage, paid resources or billing. Keep the dedicated session credential out of Preview and Development environments. Public production deployment must be accessible to reviewers.
5. Require the `Quality checks` status on main before merging; no force pushes/deletions. Vercel's Git integration automatically publishes the frontend after the merge. The GitHub push workflow checks again and publishes rules only after quality passes. These two deployments are independent; keep rule migrations backward compatible. This version only adds isolated notebook collections and preserves inherited profiles.
